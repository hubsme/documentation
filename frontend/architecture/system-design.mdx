El frontend de Hubsme sigue una arquitectura moderna de Angular con componentes standalone, carga perezosa (lazy loading) y Server-Side Rendering (SSR) mediante Express. Todo el codigo esta organizado bajo `src/` con alias de TypeScript que facilitan las importaciones entre capas.

## Estructura de directorios

```text
src/
  api/                    # Cliente API tipado (backend.api.ts)
  app/                    # Configuracion global y rutas principales
  components/             # Componentes reutilizables (toast, alert, etc.)
  enums/                  # Enumeraciones del dominio
  environments/           # Variables de entorno (dev/prod)
  functions/              # Utilidades puras (fechas Peru, etc.)
  guards/                 # authGuard y adminAuthGuard
  interfaces/             # Interfaces TypeScript
  modules/                # Modulos funcionales de la aplicacion
  routes/                 # Definicion centralizada de rutas (PATH)
  services/               # Servicios de estado y logica de negocio
```

## Alias de TypeScript

El `tsconfig.app.json` define alias que evitan rutas relativas complejas:

| Alias | Directorio |
| --- | --- |
| `@app/*` | `app/*` |
| `@service/*` | `services/*` |
| `@component/*` | `components/*` |
| `@guard/*` | `guards/*` |
| `@route/*` | `routes/*` |
| `@function/*` | `functions/*` |
| `@interface/*` | `interfaces/*` |
| `@enum/*` | `enums/*` |
| `@environment/*` | `environments/*` |
| `@module/*` | `modules/*` |

## Standalone components y lazy loading

Todos los componentes son `standalone`. Las rutas usan `loadComponent` para cargar modulos bajo demanda:

```typescript
// src/app/app.routes.ts
export const routes: Routes = [
  {
    path: '',
    loadComponent: () => import('@module/landing/landing').then((m) => m.Landing),
  },
  {
    path: 'admin/pyme',
    loadComponent: () => import('@module/admin/admin').then((m) => m.Admin),
    canMatch: [matchPyme],
    children: [ /* ... */ ]
  },
];
```

## SSR con Express

La aplicacion usa `@angular/ssr` con un servidor Express personalizado:

```typescript
// src/main.server.ts
import { bootstrapApplication } from '@angular/platform-browser';
import { App } from './app/app';
import { config } from './app/app.config.server';

const bootstrap = (context: BootstrapContext) =>
    bootstrapApplication(App, config, context);

export default bootstrap;
```

```typescript
// src/server.ts
const angularApp = new AngularNodeAppEngine();
app.use((req, res, next) => {
  angularApp.handle(req)
    .then((response) => response ? writeResponseToNodeResponse(response, res) : next())
    .catch(next);
});
```

<Info>
  En produccion, el SSR escucha en el puerto definido por la variable `PORT` (por defecto `4000`). El modo de renderizado para todas las rutas es `Client` segun `app.routes.server.ts`.
</Info>

## Inyeccion de dependencias con `inject()`

Los servicios se inyectan usando la funcion `inject()` de Angular, eliminando la necesidad de constructores en muchos casos:

```typescript
// src/guards/auth.guard.ts
export const authGuard: CanActivateFn = (route, state) => {
  const sessionService = inject(SessionService);
  const router = inject(Router);
  // ...
};
```

## Autenticacion dual

El frontend maneja dos sistemas de sesion independientes:

<CardGroup cols={2}>
  <Card title="SessionService" icon="user">

  </Card>

  <Card title="AdminSessionService" icon="shield">
    Gestiona la sesion del backoffice. Almacena `admin_session` en `localStorage` con token y rol `admin`. Usado por `adminAuthGuard`.

## Generacion del cliente tipado

El archivo `src/api/backend.api.ts` se genera automaticamente desde el Swagger del backend:

```bash
npm run generate:types
```

Este cliente se configura en `app.config.ts` con un factory que inyecta `Router`, `PLATFORM_ID` y `Injector` para manejar tokens y redirecciones 401:

```typescript
const http = new HttpClient({
  baseUrl: environment.baseUrl,
  securityWorker: async () => {
    const session = localStorage.getItem('user_session');
    if (session) {
      const token = JSON.parse(session).accessToken;
      return { headers: { Authorization: `Bearer ${token}` } };
    }
    return {};
  },
  customFetch: async (input, init) => {
    const response = await fetch(input, init);
    if (response.status === 401) {
      sessionService.removeSession();
      router.navigate([buildPath(PATH.auth.signIn)], { queryParams: { returnUrl } });
    }
    return response;
  },
});
```

<Warning>
  Nunca edites manualmente `backend.api.ts`. Si el backend cambia modelos o endpoints, ejecuta `npm run generate:types` para regenerarlo.
</Warning>
