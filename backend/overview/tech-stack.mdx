El backend de Hubsme se ejecuta sobre un stack moderno de Node.js, disenado para ofrecer una API REST confiable, con tipado estricto y facil integracion con servicios de terceros. Todas las dependencias de produccion estan definidas en `package.json` y se ejecutan con Node.js >= 20 y npm >= 10.

## Requisitos de entorno

| Requisito | Version minima |
| --- | --- |
| Node.js | \>= 20.0.0 |
| npm | \>= 10.0.0 |
| PostgreSQL | 15+ |

## Componentes principales

<CardGroup cols={2}>
  <Card title="Framework y lenguaje" icon="code">
    **NestJS 11** (`@nestjs/common` ^11.0.17) como framework principal con arquitectura modular y TypeScript 5.7.3 para tipado estricto.
  </Card>

  <Card title="ORM y base de datos" icon="database">
    **Drizzle ORM 0.44.7** (`drizzle-orm`) con PostgreSQL (`pg` ^8.16.3). Drizzle Kit 0.31.6 para migraciones y studio de base de datos.
  </Card>

  <Card title="Autenticacion" icon="lock">
    **JWT** con `@nestjs/jwt` ^11.0.2 y `passport-jwt` ^4.0.1 para autenticacion de tokens Bearer. Bcrypt ^6.0.0 para hash de contrasenas.
  </Card>

  <Card title="Validacion y documentacion" icon="file-code">
    **Class-validator** ^0.14.2 y **class-transformer** ^0.5.1 para validacion de DTOs. **Swagger** (`@nestjs/swagger` ^11.2.1) con UI en `/api`.
  </Card>
</CardGroup>

## Alias de importacion

El proyecto usa alias de TypeScript configurados en `tsconfig.json` y reflejados en Jest para mantener rutas limpias y evitar imports relativos complejos:

```typescript
import { MeetingRepository } from '@repositories/meeting.repository';
import { parseDateInPeru } from '@functions/date.function';
import { JwtAuthGuard } from '@modules/auth/jwt-auth.guard';
```

Alias disponibles: `@core`, `@models`, `@db`, `@seeds`, `@modules`, `@controllers`, `@services`, `@repositories`, `@functions`, `@utils`, `@config`.

<Info>
  El puerto por defecto de la aplicacion es **6001**. La documentacion interactiva de la API esta disponible en `http://localhost:6001/api` gracias a Swagger UI.
</Info>
