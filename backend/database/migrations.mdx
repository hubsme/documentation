Las migraciones SQL viven bajo `src/db/migrations/version_00X/` y siguen el patrón `vXXX_XXX_<descripcion>.sql`. Cada versión agrupa cambios coherentes de dominio y se aplica manualmente sobre las bases de desarrollo, staging y producción.

<Warning>
  La IA no ejecuta `db:reset`, `db:create`, `db:seed`, `db:migrate`, `db:backup` ni `db:restore`. Solo un humano autorizado aplica migraciones. En producción, un error de migración puede provocar pérdida de datos irreversible.
</Warning>

## Herramientas de apoyo

- `npm run db:studio` abre Drizzle Studio con la conexión configurada por variables de entorno para explorar el schema.
- `drizzle-kit` puede generar migraciones desde los archivos `.table.ts`, pero en Hubsme las migraciones se editan a mano para mantener control fino sobre orden y compatibilidad con datos existentes.

<Note>
  Antes de aplicar una nueva versión, respalda la base afectada. Registra en el issue asociado la fecha, el operador y la salida `psql` como evidencia.
</Note>

<Tip>
  Los cambios de columna que requieren backfill se dividen en dos migraciones: la que altera el esquema y la que actualiza filas existentes.
</Tip>
